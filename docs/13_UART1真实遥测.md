# UART1 真实只读遥测

0.9.0 在 ESP32 相机台架之外增加独立的飞控只读会话。工作台可以同时显示真实相机与横滚、俯仰、相对偏航；「设备与调试 → ESP32 实物台架」提供连接、配置查询和数值诊断。

## 已确认的实物连接

当前主板是 STM32F103C8T6，接口丝印为 **UART1**。旧资料中的 UART3/PB10/PB11 不适用于当前板卡。

| 线色 | ESP32-S3 | 飞控 UART1 |
| --- | --- | --- |
| 红 | GND | GND |
| 黑 | GPIO21 / RX | PA9 / TX1 |
| 黄 | GPIO47 / TX | PA10 / RX1 |
| 绿 | 3V3 | 3V3 |

串口为 115200、8N1，无硬件流控；ESP32 固件为 0.1.7，STM32 为 UART1 只读台架 0.2.0。当前测试用现有四线，仅由飞控 USB 供电，ESP32 两个 USB 均不接，电池断开、遥控关闭、全部螺旋桨拆除。SWD 与 UART1 是两个独立插座。此接法的台架运行记录不等于 3.3 V 额定供电或电池工况已经合格。

## 使用

1. 电脑开启已配置的 2.4 GHz 移动热点，让 ESP32 接入；从热点设备列表核对当前 IPv4。地址可能在重启后改变。
2. 打开「设备与调试 → ESP32 实物台架」，填写实际地址，点击「连接实物台架」。
3. 点击「连接 UART1 遥测」，等待 HELLO 和当前 CONTROL_STATE 建立会话。点击「读取飞控配置」查看只读、未签认配置。
4. 返回工作台可同时观察画面与姿态；重新启动软件后必须再次显式连接。
5. 需要重接线时先让两板断电。原有四线包含 3V3，勿同时接入另一路 ESP32 USB 供电。

上位机固定从配对 ESP32 UDP 12700 接收，在当前本机网络接口 UDP 12701 监听。其他测试程序占用此端口时会报告冲突，不自动换目标或扫描网段。

冷启动时网络可能先于相机就绪。显式连接后，兼容固件报告相机仍在启动时，页面保持“正在等待相机启动”，最长等待20秒；此时不发布零流号或任何图像。超时后需手动重连。已经配对的连接遇到相机重新启动仍会失效，不能用启动等待自动接纳新设备。自动对焦的合法错误码保留为诊断，不误报成整个协议不兼容。

## 数据含义

- ATTITUDE 来自飞控 MPU6050 和本地姿态估计，线单位 rad，界面转换为度。机头依据操作者确认的双箭头方向；轴向实测状态见 `uart1-public-summary.json` 的硬件摘要。相对偏航没有真北或磁航向资格。
- 每项数据同时核对协议有效位、飞控报告年龄及电脑接收后年龄；重复或倒退的 ATTITUDE 不刷新年龄。当前 300 ms 测量显示门槛只是应用台架参数。
- 高度、光流位置、电池电压仍为未知/null，不用零或模拟值补齐。
- 相机显示与姿态是独立通道，没有同步曝光、相机外参或视觉控制资格。

心跳只维持 ESP32 配对，不刷新飞控状态或传感器年龄。短暂丢包最多重发三次原 HELLO 字节，沿用原 nonce；不创建新许可或动作。新的 boot/session、ESP32 重启导致的身份变化以及恢复失败均要求显式断开、重连，旧数值清空。

## 边界与证据

电脑出口仅允许 HELLO、QUERY_PROFILE 和无控制含义的地面站心跳，不能发 PERMIT、解锁、起飞或电机命令。STM32 保留原厂本地遥控/PID/电机路径，本阶段不验收该路径或其失联处置，不可据“只读上位机”推断电机在任何输入下都被禁用。

开发窗口和目录包的实际相机/UART1 检查由 `tests/uart1_desktop_live.cjs` 显式运行；一般 `Station.ps1 check` 使用软件夹具，不打开实物。匹配当前版本的公开结果为 `evidence/uart1-public-summary.json`，完整原始记录留在本机研发目录。构建、注入测试、真实台架和飞行结论分别记录。
