# 开源仓库与版本发布

公开仓库：<https://github.com/lwhguge-dot/LF-2S>。仓库根目录是独立上位机工程；原研发工作区仍放在 `P1/05_上位机`，两者使用同一份源码。没有上传整个研发工作区、商家原件、本机环境或模型。

自有源码采用 MIT。第三方许可见根目录 THIRD_PARTY.md；Electron 自带 LICENSE 不改名，自有许可在 Windows 包内另存为 LF2S-LICENSE.txt。协议的原始字节及上游 COPYING 随源码保留。

## 本机发布步骤

1. 修改 package.json 版本并更新 package-lock.json，在 docs/releases/v版本.md 写准确的中文版本说明，更新 CHANGELOG.md。界面、后台、包名和清单从 package.json 读取同一版本。若升级 Electron，另更新 runtime-lock.json，核对官方 ZIP 和 exe 的 SHA-256；恢复脚本只使用官方地址，带超时和有限重试。
2. 执行 README 的检查、打包、目录包验收、报告、归档与解压复验命令。发布目录只包含完整 ZIP、SHA-256、manifest 和解压运行验证 JSON。
3. 检查 git diff 和暂存文件；提交源码。用与 package.json 对应的 `v版本` 标签指向该提交，正常推送 main 和该标签，不强推。
4. 已通过 Git Credential Manager/gh 登录的本机运行 `./.venv/Scripts/python.exe -B scripts/publish_release.py`。也支持进程环境 GH_TOKEN/GITHUB_TOKEN；不要把令牌写入命令、文件或聊天。脚本先上传草稿，逐一核对服务器资产大小和 SHA-256，再发布为预览版本。

发布脚本拒绝替换已发布版本或同名但内容不同的资产；修订应递增版本。失败时保留可检查的草稿，不默认删除远程内容。

## GitHub Actions

main 推送与 PR 自动执行 Windows 构建和桌面检查，上传已验证 ZIP 作为工作流产物；这些运行不会自动发布版本。

要在 GitHub 内构建并发布新版本：先推送对应标签，再打开 Actions →「Windows 构建与发布」→ Run workflow，填写 release_tag（如 v0.1.1），勾选 publish。只有依赖恢复、后台测试、真实 Electron 操作、目录包与 ZIP 解压验收全部通过后，单独的发布作业才有 contents:write 权限并创建 GitHub 预览版本。普通构建使用 contents:read，checkout 不保存 Git 凭据。

本机发版与 Actions 发版选择其一。同一个标签不重复发布。当前始终发布 prerelease；进入真实硬件或稳定版前，须根据已验收范围单独修改发布策略与标题，不能把 S2 模拟文案直接当作未来全部版本说明。

## 下载校验

```powershell
Get-FileHash -Algorithm SHA256 ./LF2S-Station-0.3.0-win-x64.zip
Get-Content ./LF2S-Station-0.3.0-win-x64.zip.sha256
```

两个哈希应完全一致。完整解压后保留整个文件夹，再运行 LF2S-Station.exe。未提供数字签名或安装器；验收范围为当前 Windows 的软件/模拟回归及单独列出的配对 ESP32 显示检查。Release 的 verification.json 记录实际从 ZIP 解压出的程序运行结果，不能替代 UART、光学时序或飞行验收。
