# 0.7.3 飞控重启会话隔离修复

在当前会话收到另一启动代数的CONTROL_STATE后，上位机应要求人员断开并重新连接。此前这个限制依赖错误文字中是否包含“重启”；随后坏包覆盖错误文字，再收到序号更大的旧启动状态，可能错误恢复在线。

现在使用独立的`reconnect_required`状态锁存重连要求：重启时停止任务重试、清空当前状态/遥测/配置，后续坏包、旧状态或旧结果均不能解除，也不能发送请求。只有显式断开清理旧会话，再进行新的HELLO和状态确认后，才恢复在线。普通坏包在没有检测到重启时，仍允许有效当前状态恢复。

复现和新增7项后台回归使用实际编译ARM的Flash日志/UART路径产生的100、101两次启动数据，以及延迟到达的旧启动更大样本号；输入为离线模型，不是实物串口。0.7.2原源码、软件结果和ZIP保留，修复不改变MAVLink线格式或开放真实控制。

当前验证结果以`evidence/acceptance.json`及`tests/test_reboot_latch.py`为准。真实ESP32套件、飞控USB、公司模型和真人普通话不因软件升级自动计为新版实测。
