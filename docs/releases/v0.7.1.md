# v0.7.1 · 修复撤权后的最终结果关联

失败END或FAILSAFE在飞控端撤权后，其自身最终回复的当前租期为0。旧后台只为CANCEL放行这种情况，因而把这两类合法回复丢弃，操作可能一直显示等待。0.7.1按请求语义接受这些终结结果，并接受租期已失效后的明确拒绝；消息类型、请求编号、操作、任务和会话继续匹配，其他非零租期不能借用这条例外。动作终结缺少事件编号时拒绝，不把受理当完成。

开发使用共同链接STM32 ARM函数实际产生的主线字节，全部位置、状态和签认配置是合成夹具。旧0.7.0回放中，失败END和FAILSAFE均停在pending；修复后分别正确归为failed和completed。当前后台84项注入检查覆盖58帧C字节、完整状态/结果、撤权及迟到结果；真实UART、闭环/电机和飞行没有接入。该检查独立于桌面和实机成绩。

新增17组关联正反例，191项后台回归、开发窗口和目录包各37项检查通过；语音界面在开发/目录包各16项测试麦克风与模拟ASR检查通过。ZIP解压运行以对应verification.json为准。0.7.0的公司文本调用、CPU样音和USB台架记录保留在各自原版本；本次没有重新完成公司语音部署、真人普通话或实物UART测试。

当前上位机保持模拟、相机／原厂USB只读台架和回放隔离，`hardware_control_allowed=false`。语音和Qwen建议仍没有许可／飞行执行出口。
