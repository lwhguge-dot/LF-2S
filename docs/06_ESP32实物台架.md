# ESP32 实物台架（0.4.0）

本页连接已到货的 ESP32-S3-N16R8 / OV5640，读取相机与板卡诊断。STM32 尚未到货，UART 与飞行动作保持关闭。协议仍为 P1 定制的 MAVLink 2 配置 `2.0.0-draft1`，指纹 `5889088805303263`；HTTP 图像和诊断是独立辅助接口，没有修改线协议。

## 使用

1. USB 接在板子的 USB-UART 口供电。电脑通过 Windows Wi-Fi 连接 `LF2S-S3-81E5` 热点，密码沿用已配置的私有台架密码。
2. 打开上位机「ESP32 实物台架」，默认 `192.168.4.1:80`，点击「连接实物台架」。此时会中断并断开模拟任务；实物连接与模拟入口互斥。
3. 观察真实 JPEG、固件、流编号、尺寸、PSRAM、UDP 校验计数及 AF 状态。连续预览默认尽快读取、上限 10 FPS，始终最多一个请求在途；可选 5 FPS 或 1 FPS 静态查看。实际显示帧率与耗时独立显示，上限不代表测得帧率。
4. 「重新对焦」只表示命令被接受。AF 状态按传感器回报显示；搜索中、未完成或状态异常时不会宣布光学对焦成功。0.1.4 固件按钮触发一次自动对焦；启动时启用连续 AF。模组实际是否具备匹配的可动镜组仍需验证。
5. 「断开实物台架」清空画面和健康状态；重新连接需显式操作。板卡重启/流号改变或身份错误会失效连接；不自动接纳新流。回放关闭实物输入，回放中不取图或对焦。

## 显示与校验

后端只访问固定 `/health`、`/preview`、`/focus` 及白名单参数 `/preview/config` 路径，不提供通用 URL 代理、重定向或动作转发。目标为局域网 RFC1918 的 IPv4 字面值；不解析主机名，不经过系统代理。单次连接超时 1 秒；预览读取 6 秒、状态 2 秒、对焦 5 秒，均由独立绝对期限中断。JPEG 最多 256 KiB，状态最多 8 KiB，传输编码与重复响应头拒绝。0.3.1 对临时传输允许三次当前流核对后恢复，身份/流/JPEG 错误立即阻断，详见 docs/07。

0.4.0 配合固件 0.1.5 增加固定 `/preview/config` 预览参数入口，最长响应 8 秒，参数白名单与流核对见 docs/08。只有这个显式设置操作可以核实下一代流并继续显示；无法核实时进入错误，不自动重试设置。旧固件继续预览，对应调整按钮禁用。界面增加 1/5/10 FPS 上限与实际显示帧率；1 FPS 不是运动识别默认值。

显示预览单独验证协议/模式、流号、请求编号、递增帧号与采集时间、显示用途标记、未标定状态、长度、MIME、真实 JPEG 解码及尺寸。64 位流号与采集微秒保持十进制字符串，避免 JavaScript 精度丢失。

这里不修改协议中的 ImageGate：它仍要求标定和合格采集。本页专门读取未标定 `/preview`，`display_only=true`、`hardware_freshness_qualified=false`，没有视觉控制资格。429 等待下一次刷新，503/504 或临时传输异常进入有界恢复；流/身份错误和连续恢复失败须断开并重新连接。页面 2 秒未收到新图像或后台状态超过 1.5 秒失效时隐藏画面。这些是显示期限，未证明传感器曝光新鲜度。

渲染进程不直连板子，不持有本地服务 token 或 Wi-Fi 密码。新增 IPC 仅有 `benchConnect`、`benchDisconnect`、`benchPreview`、`benchFocus`；主进程和 Python 后端分别验证参数。对焦由 ESP32 相机工作线程串行执行。

## 验证与待办

软件检查覆盖错误地址、身份/流/编号/尺寸、JPEG 解码、慢响应绝对期限、断开后的迟到图像和回放/模拟隔离。`tests/esp32_live.cjs` 是单独显式运行的真实板测试，不加入无硬件默认验收；由研发目录的 `bench_station.py --run` 负责有限时长 Wi-Fi 切换和独立恢复进程。实物原图/截图保留在本地，不随公开包携带。

相机光学清晰度、曝光/运动时序、内外参、供电/散热、Wi-Fi 长时稳定性、STM32 真实协议、故障处置及飞行未据此验收。STM32 适配继续按用户决定等待到货。
